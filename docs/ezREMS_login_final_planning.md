# 이지램스(ezREMS) 로그인 개편 최종 기획서

버전: V5 · 업데이트: 2026-09-21

## 1. 목표

로그인을 가장 빠른 핵심 과업으로 유지하면서 왼쪽 마케팅 패널을 공지·브랜드·고객사 사례 채널로 활용합니다. 운영자는 코드나 데이터베이스를 직접 다루지 않고 관리자 화면에서 콘텐츠를 관리합니다.

## 2. 로그인 서비스 페이지 구조

로그인 서비스는 역할이 다른 3개 공개 화면으로 구성합니다. 세 화면은 `login/` 저장소에서 함께 관리하고 GitHub Pages로 배포합니다.

| 화면 | 소스·운영 경로 | 목적 | 주요 구성 |
|---|---|---|---|
| 로그인 페이지 | `login/index.html` · `/ezrems-login-renewal/` | 계정 인증 시작점 | 마케팅 패널, 긴급공지, 고객사 슬라이드, IP·위치 안내, 아이디·비밀번호, 오류 메시지, 로그인 버튼 |
| 2차 인증 페이지 | `login/two-factor.html` · `/ezrems-login-renewal/two-factor.html` | 1차 로그인 성공 후 추가 본인 확인 | SMS·이메일 선택, 6자리 코드, 3분 타이머, 재발송, 인증 확인, 로그인 화면 복귀 |
| 고객 공개 페이지 | `login/customers/index.html` · `/ezrems-login-renewal/customers/` | 일반 방문자 대상 고객·성과 홍보 | 자산 포트폴리오, ERP 현황, 고객사 카드, 업종·키워드·성과, 도입 문의 |

### 2.1 로그인 페이지

- 왼쪽은 마케팅 슬라이드, 공통 패널 배경, 페이지 전체 배경, 고객사 로고 슬라이드로 구성합니다.
- 오른쪽은 IP·위치 안내, 아이디/이메일, 비밀번호, 로그인 오류 메시지, 로그인 버튼과 도움말로 구성합니다.
- `전체 성공 사례 보기`는 고객 공개 페이지를 새 탭으로 엽니다.
- 공통 배경은 슬라이드별 속성이 아니라 마케팅 패널 전체에 적용되는 재사용 테마입니다. 패널형과 카드형 배경 모드를 지원하고 이미지가 없으면 기본 그라데이션을 사용합니다.

### 2.2 2차 인증 페이지

- 로그인 페이지와 동일한 Paperlogy, 색상, 여백, 버튼 위계를 사용하되 인증 과업에 집중하도록 로고와 서비스 타이틀은 반복하지 않습니다.
- SMS 또는 이메일로 받은 6자리 일회용 코드를 입력하며 기본 유효시간은 3분입니다.
- 만료·오입력·재발송 결과를 입력 영역 인근의 텍스트 메시지로 안내하고 키보드 붙여넣기와 자리 자동 이동을 지원합니다.
- `로그인 화면으로 돌아가기`는 브라우저 이력이 있으면 이전 화면, 없으면 `index.html`로 이동합니다.
- 현재 화면은 UI 목업이며 실제 코드 발송·검증·세션 발급은 내부 인증 시스템과 연동해야 합니다.

### 2.3 고객 공개 페이지

- 관리자 주소를 노출하는 공개 화면 대신 로그인 GitHub Pages 하위의 `/customers/`에서 운영합니다.
- 고객사 데이터와 로고는 Cloudflare의 공개 콘텐츠 API에서 읽으며 관리자 화면과 쓰기 API에는 접근하지 않습니다.
- 공개 고객사는 고객사명과 로고를 포함해 표시합니다. 비공개 고객사는 이름을 마스킹하고 로고를 숨기되 업종·자산구분·시스템구분·키워드·성과는 표시합니다.
- 현재 운영 고객사 데이터는 30건 모두 공개 상태입니다.
- 기존 관리자 도메인의 `/customers`, `/customers.html`, `/customres`는 로그인 사이트 고객 공개 페이지로 리디렉션합니다.

세 화면의 기본 글꼴은 Paperlogy이며 CDN 실패 시 Noto Sans KR·시스템 글꼴로 대체합니다.

## 3. 동적 콘텐츠 범위

| 데이터 | 저장소 | 공개 API |
|---|---|---|
| 긴급공지 | Cloudflare KV | `/api/public-content/emergency-notice` |
| 마케팅 패널·배경 테마 | Cloudflare KV, 이미지 R2 | `/api/public-content/marketing-slides` |
| 고객사 데이터 | Cloudflare KV, 로고 R2/정적 자산 | `/api/public-content/client-references` |

이 3종 외의 화면 설정은 현재 동적 연동 범위에 포함하지 않습니다.

## 4. 시스템 구조

```text
관리자 페이지(Cloudflare Pages)
  ├─ Cloudflare Access 이메일 로그인
  ├─ Access JWT 서명·AUD·만료·관리자 이메일 검증
  ├─ JSON → Pages Functions → KV
  └─ 이미지 → Pages Functions → R2

로그인 페이지(GitHub Pages)
  ├─ 콘텐츠 공개 API → Cloudflare KV/R2
  ├─ IP 위치 API → Cloudflare
  ├─ 로그인 계정 → 내부 인증 시스템(향후 실제 연동)
  ├─ 1차 인증 성공 → 2차 인증 페이지 → 서비스 진입
  └─ 전체 성공 사례 → 고객 공개 페이지(새 탭)

고객 공개 페이지(GitHub Pages)
  └─ 고객사 공개 API·로고 → Cloudflare KV/R2
```

관리자 저장은 GitHub API 커밋 방식이 아닙니다. 콘텐츠를 수정해도 로그인 저장소를 다시 배포할 필요가 없고 다음 페이지 로딩부터 공개 API의 최신 값을 사용합니다.

## 5. 외부 연동 원칙

### 5.1 로그인 콘텐츠

`https://ezrems-login-admin.pages.dev`를 기준 출처로 사용합니다. 각 요청은 `cache: no-store`이며 실패 시 로그인 폴더의 로컬 폴백 데이터를 사용해 화면이 비지 않게 합니다.

### 5.2 IP 위치정보

`/api/location`에서 접속 IP 기반의 대략적인 도시·지역·국가를 표시합니다. GPS 정밀 위치가 아니며 5초 타임아웃 또는 오류 시 “확인 불가”로 표시하되 로그인은 계속 사용할 수 있어야 합니다.

### 5.3 로그인 계정 연동

현재 `login/index.html`의 제출 처리는 UI 목업입니다. 실제 배포 전에 내부 인증 API로 교체해야 하며 다음 원칙을 적용합니다.

- HTTPS POST로만 전송
- 비밀번호를 로컬 저장소·로그·URL에 기록하지 않음
- 실패 코드를 사용자 친화적 메시지로 변환
- 연속 실패 제한, 세션 발급, 2차 인증 전환은 내부 정책 준수
- 콘텐츠 API와 인증 API의 도메인·권한·로그를 분리

## 6. 관리자 기능

- 긴급공지 활성화, 기간, 등급, 제목과 본문 관리
- 마케팅 슬라이드 추가·수정·삭제·노출 순서 관리
- 공통 배경 테마 신규 등록 팝업, 저장 테마 선택·수정·삭제·재사용
- 배경 이미지 R2 업로드와 즉시 미리보기
- 고객사명, 시스템구분, 자산구분, 관리자산 수, 세대(Unit), 면적(m²), 핵심 키워드, ERP, 로고 관리
- 고객사 통계/보고서 화면
- GitHub Pages 로그인 화면 통합 미리보기(데스크톱·모바일·새로고침·새 창)
- 저장 중 진행 상태와 성공·실패 메시지

## 7. 디자인 가이드

| 용도 | 굵기 |
|---|---|
| 페이지·중요 영역 제목, 핵심 실행 버튼 | 700 |
| 상태 배지, 선택 상태, 보조 버튼 | 600 |
| 입력 라벨, 순위, 작은 데이터 라벨 | 500 |
| 본문, 설명, 출처, 일반 데이터 | 400 |

800 이상은 사용하지 않습니다. 같은 행의 데이터명과 수치를 모두 굵게 표시하지 않으며, 중요도는 색상뿐 아니라 굵기·위치·아이콘·상태 문구로 함께 표현합니다.

## 8. 배포 및 운영

- 관리자 소스: `admin/`을 `https://github.com/ZEONS/ezrems-login-content-admin`의 `main` 브랜치에 푸시하면 Cloudflare Pages 프로젝트 `ezrems-login-admin`이 자동 배포
- 로그인 소스: `login/`을 `https://github.com/ZEONS/ezrems-login-renewal`에 직접 업로드하여 GitHub Pages 배포
- 관리자 운영 주소: `https://ezrems-login-admin.pages.dev/admin`
- 로그인 운영 주소: `https://zeons.github.io/ezrems-login-renewal/`
- 2차 인증 운영 주소: `https://zeons.github.io/ezrems-login-renewal/two-factor.html`
- 고객 공개 운영 주소: `https://zeons.github.io/ezrems-login-renewal/customers/`

관리자 소스는 GitHub 자동 배포를 운영 기준으로 사용합니다. Wrangler 직접 배포는 자동 배포 장애 시에만 사용하는 비상 복구 절차입니다.

## 9. Cloudflare Access 설정과 운영

### 9.1 최초 설정

1. Cloudflare Zero Trust의 Access applications에서 Self-hosted 애플리케이션을 만듭니다.
2. 공개 호스트는 `ezrems-login-admin.pages.dev`, 경로는 `admin*`로 지정합니다.
3. Allow 정책의 Include 조건에 관리자 이메일을 등록합니다.
4. Worker 환경 변수 `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`, `ACCESS_ADMIN_EMAIL`을 설정하고 다시 배포합니다.
5. `ADMIN_API_TOKEN`은 브라우저에서 입력하거나 노출하지 않고 장애 복구용 서버 인증 수단으로만 유지합니다.

현재 운영 정책의 기본 세션은 24시간입니다. 운영 보안 정책에 따라 Access 애플리케이션 또는 정책에서 더 짧게 조정할 수 있습니다.

| 경로 | 접근 정책 |
|---|---|
| `/admin`, `/api/content`, `/api/assets`의 쓰기 요청 | Cloudflare Access 인증 및 Worker JWT 검증 |
| `/api/public-content/*`, `/api/location` | 로그인 화면에서 사용하는 공개 읽기 |
| `/content/images/backgrounds/*`, 공개 이미지 조회 | 로그인 화면에서 사용하는 공개 읽기 |

### 9.2 관리자 추가·삭제

관리자를 추가할 때는 Access Allow 정책과 Worker 허용 이메일 설정을 함께 변경해야 합니다. 한쪽만 변경하면 Access 로그인 후에도 Worker가 401을 반환할 수 있습니다.

1. Access Allow 정책의 Emails에 관리자를 추가하거나 삭제합니다.
2. `ACCESS_ADMIN_EMAIL` 또는 향후 다중 이메일 허용 목록을 동일하게 변경합니다.
3. Worker를 재배포합니다.
4. 시크릿 창에서 신규 계정 로그인, 조회, 저장, 이미지 업로드를 검증합니다.

### 9.3 일상 운영

1. `/admin`에 접속해 회사 이메일로 인증합니다.
2. 긴급공지, 마케팅 패널·배경 테마 또는 고객사 데이터를 수정합니다.
3. 저장 진행 표시가 완료되고 성공 메시지가 나온 것을 확인합니다.
4. 통합 미리보기를 새로고침해 GitHub Pages 로그인 화면의 반영 결과를 확인합니다.
5. 문제가 있으면 공개 API 응답, 최신 Wrangler 배포, KV/R2 바인딩 순서로 점검합니다.

## 10. 완료 기준

- 관리자 저장 후 새로고침해도 KV 데이터가 유지됨
- 업로드한 테마 이미지가 R2에서 다시 조회되고 미리보기에 표시됨
- 로그인 새로고침 시 콘텐츠 3종이 최신 값으로 반영됨
- API 장애 시 폴백 콘텐츠와 “확인 불가” 안내로 화면 기능이 유지됨
- 로그인 오류 메시지 영역과 키보드 접근성이 정상 동작함
- 실제 서비스 적용 전 내부 인증 API와 2차 인증 연동을 별도 검증함
- 1차 인증 성공 시 2차 인증 페이지로 이동하고 인증 성공 시 내부 서비스로 진입함
- 고객 공개 페이지가 새 탭으로 열리고 고객사 공개 API·로고·ERP 집계가 정상 표시됨
- 루트 주소는 `/admin`으로 이동하고 Access 로그인 이후 관리자 화면이 한 번만 열림
- 비인가 사용자는 관리자 화면과 쓰기 API를 우회할 수 없고 공개 콘텐츠 API는 정상 조회됨
